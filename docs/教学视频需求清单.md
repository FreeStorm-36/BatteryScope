> 编制日期：2026-10-15
> 对应代码：`src/data/videos.js`（全站唯一视频清单）｜`src/components/VideoSlot.vue`（视频位组件）
> 用途：本文档既是**给你的找片/自录标准**，也是交付时的**素材登记表**。

## 0. 先说结论

**我建议走"本地自托管"路线，而不是嵌入 B 站等平台的播放器。** 原因有四条，都是硬的：

| # | 问题 | 说明 |
|---|---|---|
| 1 | **断网就白屏** | 答辩现场、评审电脑、科技馆展项都可能没有网络或屏蔽外链。嵌入播放器一断网就是一个空白框。 |
| 2 | **版权与原创性** | 竞赛规则要求"涉及第三方素材应合法使用并注明来源"。整段嵌入他人视频，评审会直接质疑作品的原创性份额——（七）赛道的作品要求第 2 条还专门写着"不得以技术展示替代必要的教育或科普内容设计"。 |
| 3 | **无法保证科学性** | 这个项目最硬的资产就是"每处内容都有依据"。网上的科普视频我无法逐帧核对，万一里面讲错一处（比如"电子穿过隔膜"），反而成了扣分点。 |
| 4 | **观感被破坏** | 平台播放器自带推荐、弹幕、水印、片头广告，和本作品统一的深蓝科技调完全冲突。 |

**所以正确做法是：把视频文件放到本地，由页面的 `<video>` 标签播放。** 三条获取路径：

| 路径 | 版权 | 离线可用 | 与页面的一致性 | 推荐度 |
|---|---|---|---|---|
| **A. 自己录制 / 自制动画** | 完全自有 | ✓ | 最高 | ★★★★★ |
| **B. 用 CC / 公有领域素材二次剪辑** | 署名即可用 | ✓ | 中高 | ★★★★ |
| **C. 平台播放器嵌入** | 有风险 | ✗ | 差 | ★★（仅可作"延伸观看"） |

**最小可行方案**：如果时间紧，优先做 **A** 里的「页面录屏 + 口播」——用本作品自己当素材，录制成本最低，而且天然和页面口径一致（不可能讲错）。第 05、06、07 章的三条视频都可以这么干。

## 1. 统一技术规格（所有视频都要满足）

| 项目 | 要求 | 说明 |
|---|---|---|
| 分辨率 | **1920×1080（16:9）** | 页面播放器按 16:9 容器排布，其他比例会留黑边。竖屏素材不采用。 |
| 帧率 | **25 或 30 fps** | 录屏用 30 fps 更稳。不要 60 fps（体积翻倍，收益为零）。 |
| 编码格式 | **MP4（H.264 + AAC）** | 兼容性最好。不要用 H.265/HEVC，部分浏览器播不了。 |
| 码率 | 1080p 建议 **6—10 Mbps** | 再高没意义，再低会糊。 |
| 单文件大小 | **≤ 60 MB** | 页面是静态站点，视频会随站点一起分发；太大首屏会拖慢。超了请告诉我，我改成分段/延迟加载。 |
| 时长 | **30 秒 — 120 秒**（各条有具体要求） | 这是"补充讲解"的定位，不是正片。超过 2 分钟注意力就跑了。 |
| 音频 | **有人声讲解**，音量均值约 -16 LUFS，峰值不超 -1 dBFS | 纯 BGM 无讲解的视频，教学价值会大打折扣。 |
| 字幕 | **必须有中文字幕** | 硬字幕（烧进画面）最省事。必须是中文；专有名词可中英并列。 |
| 片头片尾 | **不要**第三方 logo、水印、平台角标、订阅引导 | 也不要有片头广告。 |
| 画面内 | **不要出现播放器 UI**（进度条、暂停按钮等） | 录屏时请隐藏或裁掉。 |
| 背景音乐 | 可选，但**必须是有授权的**（无人声段可留白） | 用无版权音乐库（如 Pixabay Music、YouTube 音频库的 CC 内容）。 |

> ⚠️ 有一个容易忽略的点：**画面里不要出现未经授权的商标**。比如实拍拆解时若拍到某品牌电芯的完整商标，需要打码或用通用电芯替代。

### ① `ch02-teardown.mp4` ｜ 第 02 章 · 电芯展柜

| 项目 | 内容 |
|---|---|
| **标题** | 圆柱电芯拆开看：钢壳、卷芯、极耳与防爆阀 |
| **时长** | 60—90 秒 |
| **形式** | **实拍优先**（剖切件或拆解视频），其次高质量三维动画 |
| **配套内容** | 与"三维展台拆解"配套 |

**必须覆盖：**
1. 外壳为钢壳，顶部有正极帽与防爆阀（安全阀）结构
2. 内部是正负极与隔膜叠合后**卷绕**而成的"卷芯"
3. 卷芯叠层顺序：**正极 → 隔膜 → 负极 → 隔膜**
4. 极耳把卷芯两端引出到外壳与顶盖；隔膜只允许离子通过、阻挡电子

**不要出现：** "电池内部是液态锂"这类错误表述；破坏满电电芯的危险操作。

**找素材的关键词：** `18650 电芯 拆解`、`圆柱锂电池 剖切`、`battery cell teardown`、`cylindrical cell cross section`

### ② `ch03-ion-path.mp4` ｜ 第 03 章 · 充放电实验台

| 项目 | 内容 |
|---|---|
| **标题** | 锂离子在充放电中的迁移路径 |
| **时长** | 30—60 秒 |
| **形式** | 微观动画（示意即可，但物理必须准确） |
| **配套内容** | 与"Li⁺ 与电子双路径"配套 |

**必须覆盖：**
1. 充电：Li⁺ 从正极脱出 → 穿过电解液 → 透过隔膜 → 嵌入负极
2. 同一时刻电子从正极经**外电路**流向负极
3. 放电：方向反过来，Li⁺ 回正极，电子经外电路回正极
4. 强调"**离子走内部、电子走外部**"两条并行的路径

**不要出现：** "电子穿过隔膜""电子在电解液里游动"——电解液与隔膜是**电子绝缘体**，这是最常见的错误。

**找素材的关键词：** `锂离子 充放电 动画`、`lithium ion battery working principle animation`、`Li-ion charge discharge animation`

> 💡 这条最适合自己用 Three.js/剪辑软件做——本作品第 03 章的 3D 场景本身就是这个动画，直接录屏 + 配音即可，且天然准确。

### ③ `ch03-cccv.mp4` ｜ 第 03 章（第二条）

| 项目 | 内容 |
|---|---|
| **标题** | CC-CV 充电：为什么最后要转恒压 |
| **时长** | 45—90 秒 |
| **形式** | 口播 + 曲线演示 |
| **配套内容** | 与"倍率—电压—功率读数"配套 |

**必须覆盖：**
1. 恒流（CC）段：电流恒定，电压随充电推进逐渐上升
2. 到达截止电压（本例 4.2 V）后转**恒压（CV）**段
3. CV 段电流逐步**衰减**，降到设定值时结束充电
4. 恒压段存在的必要性：避免过充，同时尽可能把容量充饱

**不要出现：** "恒压段电流还会变大"这类与物理过程矛盾的描述。

**找素材的关键词：** `CC-CV 充电 原理`、`lithium battery CC CV charging explained`、`恒流恒压充电 曲线`

### ④ `ch04-sei.mp4` ｜ 第 04 章 · 老化观测舱

| 项目 | 内容 |
|---|---|
| **标题** | SEI 膜：电池"生来就有"的一层膜 |
| **时长** | 45—75 秒 |
| **形式** | 动画示意 + 讲解 |
| **配套内容** | 与"SEI 增厚"机制卡配套 |

**必须覆盖：**
1. SEI 在**首次充电**时由电解液在负极表面分解形成
2. 它**既是保护层**（阻止电解液继续大量分解），**也会持续缓慢增厚**
3. 增厚的代价：永久消耗可循环锂，容量随之下降
4. 生长速率先快后慢（扩散受限）

**不要出现：** 把 SEI 描述成"纯有害"或"纯有益"——它同时具备保护作用与副作用，这是本作品在页面上的口径。

**找素材的关键词：** `SEI 膜 锂电池`、`solid electrolyte interphase animation`、`SEI layer battery aging`

### ⑤ `ch04-plating.mp4` ｜ 第 04 章（第二条）

| 项目 | 内容 |
|---|---|
| **标题** | 析锂与枝晶：快充和低温下最危险的那件事 |
| **时长** | 45—75 秒 |
| **形式** | 动画示意 + 讲解 |
| **配套内容** | 与"析锂"机制卡配套 |

**必须覆盖：**
1. 低温或大倍率充电时，锂来不及嵌入负极
2. 锂在负极表面直接以金属形式析出，形成**枝晶**
3. 后果一：析出的锂失去活性，容量直接损失
4. 后果二：枝晶可能**刺穿隔膜**，造成内短路的安全隐患

**不要出现：** 演示或鼓励拆解、穿刺、短路等危险操作。

**找素材的关键词：** `析锂 枝晶 锂电池`、`lithium plating dendrite animation`、`fast charging lithium plating`

## 3. 文件命名与交付方式

**命名必须与代码清单一致**（`src/data/videos.js` 的 `file` 字段），一个字符都不能差：

```
ch02-teardown.mp4
ch03-ion-path.mp4
ch03-cccv.mp4
ch04-sei.mp4
ch04-plating.mp4
ch05-nasa.mp4
ch06-methods.mp4
ch07-holdout.mp4
```

**两种交付方式，任选：**

1. **直接发给我** —— 把文件发过来，我来放进 `public/media/` 并改配置、重新构建、验证播放。
2. **自己放** —— 放进 `public/media/` 目录，然后把 `src/data/videos.js` 里那条的
   `status` 改成 `'ready'`、`src` 填 `media/文件名.mp4`、补上 `source` 与 `license`。

配置示例（以第 03 章第一条为例）：

```js
{
  id: 'ch03-ion-path',
  status: 'ready',                    // ← 改成 ready
  src: 'media/ch03-ion-path.mp4',     // ← 填相对路径（不要写开头的斜杠）
  poster: 'media/ch03-ion-path.jpg',  // ← 可选，封面帧；没有就留空
  source: '本团队自制',                // ← 必填：来源标注（会显示在播放器下方）
  license: ''                         // ← 若非自制，填授权方式，如 'CC BY 4.0'
}
```

> 未填 `src` 的条目即使把 `status` 改成 `ready` 也不会渲染——这是我故意加的保险，
> 避免交付版里出现一个空白播放器。

## 4. 版权与来源标注要求

竞赛规则原文要求："涉及第三方素材、数据、模型、代码应**合法使用并注明来源**"。
每条视频都必须能说清来源，我会在播放器下方显示这行字：

| 情形 | `source` 填法 | `license` 填法 |
|---|---|---|

| 用 CC 素材剪辑 | `改编自 <作者> 的《<原作名>》` | `CC BY 4.0`（按其实际协议填） |
| 公有领域素材 | `素材来源：<机构>（公有领域）` | `Public Domain` |
| 已获授权 | `<权利人> 授权使用` | `授权编号 / 日期` |

**如果用的是 B 站等平台的视频**：即使只截取片段，也必须注明作者与视频链接，
且**建议只作为"延伸观看"单独成条**，不要混在教学内容里——风险由你判断，我不建议。
