# BatteryScope V3.3 需求对照与优化报告

## 1. 核验基线

本次已完整读取并对照三份原始需求：

1. BatteryScope 任务书：定义七章、基础技术栈和初版交互；
2. BatteryScope 改进设计方案：重构叙事边界、3D、数据与预测职责；
3. BatteryScope V3 详细修改意见：给出最新 P0/P1、逐页验收和科学性边界。

三份文档存在迭代冲突时，采用“V3 详细修改意见 > 改进设计方案 > 初版任务书”的优先级。例如：初版任务书不使用 Three.js，而后两份明确要求 3D；当前实现按后续文档采用 Three.js。初版提出全自动导览，改进设计方案改为人工录制、交互可复位；当前以可重复触发和复位为准。

状态定义：

- 已实现：源码中存在，可通过构建或交互验证；
- 部分实现：核心路径可用，但尚未达到比赛级资产或完整验收；
- 未实现：不应在答辩中声称已经完成。

## 3. 本轮主动修正

1. 重做全局品牌导航、基础配色、首页和章节页尾。
2. 首页统一主角为 BS-01，不再混入三种独立标本。
3. 修复首页未销毁 interval 的资源泄漏。
4. 补齐 Types 页 wrap 热点词条。
5. 修正 DataLab 的错误同工况结论。
6. 降低对 80%、SEI 和局部容量波动的因果表述强度。
7. DataLab 的回放位置与显示点分离，显示点始终吸附实际数据记录。
8. 故事模式改为 5 个关键点逐点讲解。
9. 新增数据可信度抽屉。
10. 统一主要交互图标。
11. Sass 改用 modern compiler API，消除 legacy-js-api 构建警告。
12. npm 默认镜像改为本次实际连通的 npmmirror，并避免要求全局安装 Express。

## 5. 仍需后续投入的优化

优先级从高到低：

1. 用 Blender/GLB/PBR 替换核心程序化模型，并增加静态备用帧；
2. 在目标 Windows 设备执行 1920×1080、10 分钟、45 fps 性能验收；
3. 为 NASA 原始 .mat 提取保留 sourceCycleIndex，并公开提取脚本和字段字典；
4. 将 DataLab 局部趋势升级为冻结参数的稳健线性回归与表观回升分类；
5. 完成真实 PINN 训练、按电池划分的验证/测试、MAE/RMSE/EOL 误差与区间覆盖率；
6. 为章节切换加入真正的镜头连续转场和 3D 加载失败降级；
7. 若展示视频确需无人值守，再单独实现全站自动导览；当前 V2 方案优先支持人工录制和一键复位。

## 6. 答辩建议口径

建议表述：

> BatteryScope 已完成同一电芯的跨尺度交互科普、NASA 容量/SOH 数据读取、三类方法对比，以及一个基于真实历史、可留出回测的稳健预测基线。PINN 当前是明确的研究路线和接口边界，后续将通过独立训练和跨电池测试替换基线。

不建议表述：

> 已训练出高精度 PINN，可以准确预测任意锂电池寿命。
