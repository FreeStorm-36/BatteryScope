## 1. 赛项匹配

### 1.1 选择规则（指南第五部分原文）

> 各参赛团队提交参赛作品，请**先判断作品是否直接响应指定命题**；未直接响应指定命题的，再**根据作品的主要目标、核心功能和最终成果形态选择自主选题赛项**。跨类别作品**选择最能体现其核心创新和主要工作量的赛项**。

按这三层逻辑逐层筛。

### 1.2 第一层：七个指定命题（全部排除）

| # | 指定命题 | 排除理由 |
|---|---|---|
| 一 | "科幻+及元宇宙数字作品" | 赛道说明要求"科幻创意…结合**科幻叙事**"，评审重点第一条即"重点考察作品的**科幻设定**"。BatteryScope 是数据驱动的硬核科普，强行科幻化会直接摧毁"知识准确性"这一最大优势。**排除** |
| 二 | AIGC 类数字创意作品创作 | 要求以生成式 AI 驱动内容生成。本作品产物全部由程序化 3D + 实测数据生成，非 AIGC 产物。**排除** |
| 三 | "红色之旅 追梦铸魂" | 题材完全不符。**排除** |
| 四 | "乡村振兴 科创赋能" | 题材完全不符。**排除** |
| 五 | "民族文化 创新表达" | 题材完全不符。**排除** |
| 六 | "科技+创意，讲好中国故事" | 题材可勉强靠（"中国科技创新故事"），但该赛道取向是**叙事/传播**（短片、动画、互动网页、跨媒体方案），而非"可操作的科学系统"。我们的核心工作量在交互系统而非叙事。**排除** |
| 七 | "虚幻引擎（UE）作品创作" | 要求"基于虚幻引擎完成核心开发或制作"。本项目为 **Three.js / WebGL**，引擎不符。**硬性排除** |

→ 结论：走**自主选题类**。

### 1.3 第二层：八个自主选题（三个候选）

| # | 自主选题赛项 | 匹配度 | 判断 |
|---|---|---|---|
| 一 | 虚拟现实（VR/AR/MR/XR）与游戏类 | ★★★☆ | 有 3D 场景与交互逻辑，但无 XR 设备支持，"游戏"也不成立。评委易质疑"这不算 XR"。**不选** |
| **二** | **移动与网络应用开发类** | ★★★★ | 硬要求（可运行版本 / 系统说明 / 功能演示 / 界面截图 / 技术架构 / 测试说明）我们**全部具备且质量很高**；但**无后端、无用户系统、无数据持久化**，"功能完成度"与竞争者的小程序/APP 对比会显薄。**备选** |
| 三 | 影视与动漫创作类 | ★★ | 作品非视听创作。**不选** |
| **四** | **数字艺术与可视化设计类** | ★★★★★ | 参赛方向"三维模型、场景和视觉系统设计""信息可视化、数据可视化和交互视觉设计"**完全对口**；硬门槛"数据可视化作品应说明数据来源、处理方法、信息结构和可视化逻辑"恰是我们的强项。**第二选择** |
| 五 | 智能产品与硬件创意类 | ★☆ | 无硬件实体。**不选** |
| 六 | 人居环境与空间设计类 | ★ | 不符。**不选** |
| **七** | **智慧教育与科普创作类** | ★★★★★ | 赛道说明"面向智慧教育、数字学习、科学传播和科普服务等具有**明确知识目标和受众对象**的作品"——与本作品"硬核科普"定位几乎逐字吻合。**主推** |
| 八 | 其他创新作品类 | —— | 该赛项明确要求"只有技术组合或主要成果**无法按前述类别认定时**"才选。我们可准确归类，**不选** |

### 1.4 第三层：主推赛项的核心论证

**为什么（七）优于（四）——三条硬理由：**

1. **对手结构不同**。（七）的参赛主体多是课件、微课、科普短视频、知识问答小程序——**几乎没有同量级的实时 3D 交互系统**。我们的"技术实现"这一条会成为显著超额项。（四）的对手是视觉/设计强队，"视觉审美"上我们会被拿去和纯艺术作品比较，我们的工业科技风不占便宜。

2. **评审重点的排序对我们有利**。（七）评审重点第一条是**"知识准确性"**——这正是本项目投入最多、证据链最硬的地方：
   - 数据来自 NASA PCoE Battery Dataset 四颗 18650 实测记录（B0005/B0006/B0007/B0018）
   - 趋势模板可复现：重跑 `scripts/gen-trend-template.cjs` 与仓库内 `src/data/nasa/trendTemplate.js` **diff 完全一致**
   - 全站统计/资料类数字均带常驻口径声明，页面可见（非仅代码注释）
   - 预测为 Theil–Sen 稳健斜率 + 指数外推，带**留出法回测**（误差 4 次），并明确声明"不等同于 PINN 置信区间"
   - 已完成一轮全站数据真实性审计，订正 2 处不实（1C 电流取值、目录时长单位）

3. **（七）的作品要求第 2 条是筛人门槛**：

   > "涉及科学、历史或专业知识的，应确保内容准确并注明资料来源；**不得以技术展示替代必要的教育或科普内容设计**。"

   大量队伍会栽在这句上——交出一个炫技 3D 却没有真实知识结构。我们有真实知识结构，**只需要把"教育设计"这层补出来就能形成碾压**。

**（四）的适用场景**：如果团队更想突出"3D 建模 + 数据可视化"的技术与视觉含量，或指导老师来自设计/艺术方向，则选（四）。注意（四）要求"第三方素材、字体、模型和贴图的，应注明来源和授权情况"——本项目为程序化建模 + 系统字体，需在文档中说明清楚（这反而是加分点）。

> ⚠️ **只能选一个**。指南明确：每件作品只能选择一个赛道类型及其对应的一个作品赛道或赛项，不得以相同或实质相同作品重复申报、多头申报。

## 3. 主推赛项（七）专属要求逐条对表

### 3.1 赛道说明

> 面向智慧教育、数字学习、科学传播和科普服务等具有**明确知识目标**和**受众对象**的作品。

**现状**：定位清晰（硬核科普），但"知识目标"与"受众对象"都未在作品内明确表达。

### 3.2 作品要求逐条对表

| 要求 | 现状 | 需补 |
|---|---|---|
| (1) 面向**明确的教育对象或科普受众**，具有清晰的**知识结构**、**内容目标**、交互机制和**使用场景** | 交互机制 ★★★★★；知识结构隐含在 7 章里但未显性化；**教育对象、内容目标、使用场景均缺失** | ① 锁定受众；② 知识图谱；③ 学习目标；④ 使用场景 |
| (2) 确保**内容准确**并**注明资料来源**；不得以技术展示替代必要的**教育或科普内容设计** | 内容准确性 ★★★★★ 有硬证据；资料来源仅存在于代码注释与"数据可信度"抽屉，**未集中、未按引用格式呈现**；教育环节设计薄弱 | ① 新增「资料来源与科学口径」页；② 每章补学习目标/关键概念/常见误解；③ 增加自测互动 |

**① 明确受众（建议主锚点）**

- **主**：高校储能科学、电化学、电气工程相关专业**本科低年级**学生（对应《储能原理与技术》《电池管理系统》等课程先修/复习环节）
- **辅**：理工科通识科普受众、科技馆/实验室开放日参观者
- **不建议**面向中学生作为主受众——现有内容涉及 Theil–Sen、留出回测等概念，认知负荷不匹配

**② 知识图谱（7 章 → 知识点 → 认知层次）**

建议在文档与作品内各出一版（作品内可做成首页入口或独立页）：

| 章 | 知识点 | 认知层次 |
|---|---|---|
| 01 首页 | 锂离子电池基本构成与观察对象界定 | 识记 |
| 02 结构 | 圆柱/方形/软包形态差异；卷芯叠层；极耳与集流体功能 | 识记 + 理解 |
| 03 工作 | 充放电锂离子迁移；SEI；倍率与电压/功率关系；CC-CV | 理解 + 应用 |
| 04 老化 | 容量衰减与内阻增长；六类老化机制；多尺度损伤 | 理解 |
| 05 数据 | 容量/SOH 定义与计算；工况差异；数据可信度判别 | 应用 + 分析 |
| 06 模型 | 物理模型 / 数据驱动 / 融合方法对比与适用边界 | 分析 |
| 07 预测 | 趋势外推；留出法回测；预测区间含义 | 分析 + 评价 |

**③ 学习目标（每章 2—3 条可检验的目标）**

写法示例（第 03 章）："学完本章，能够说出锂离子充电时从正极脱出、经电解液与隔膜嵌入负极的完整路径；能够解释为什么倍率越高、可用容量越低；能够说明 CC-CV 中恒压段存在的必要性。"

**④ 使用场景（写 3 个，越具体越好）**

- 课堂演示：教师投屏，用第 03/07 章替代板书图示，现场调倍率看读数变化
- 课后自学：学生按 01→07 顺序完成，末尾自测检验
- 开放日/展项：手机扫码打开，单人 5 分钟走完七章

**⑤ 新增「资料来源与科学口径」页**（这条同时服务于 (四) 赛道的硬门槛）

内容应包含：数据源清单（NASA PCoE Battery Dataset，含四颗电芯的额定参数、充放电制度、截止电压、EOL 判据）｜每张图的依据与处理方法｜公式出处｜概念性内容的"定性/示意"声明｜第三方素材与依赖许可｜引用格式（建议 GB/T 7714）。

> 现有素材已足够支撑这一页：`README.md` §五"科学口径"、`docs/需求对照与优化报告.md`、数据实验室的"数据可信度说明"抽屉，以及本轮数据真实性审计结论。**是整理工作，不是重新研究。**
